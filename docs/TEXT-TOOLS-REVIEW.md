# 텍스트 정리 기능 검토

2026-11-06. 대상: 선택형 12개, 빠른 정리 4개, 포함 줄 삭제와 치환. 사용 빈도 자료는 없으며 아래 평가는 사용 사례와 기능의 차이를 기준으로 합니다. 기능 삭제·통합은 이번 변경에 포함하지 않습니다.

## 검증 증거 기록 원칙

각 기능의 예상 출력은 테스트에 독립적인 문자열로 작성합니다. Core 결과를 UI 테스트의 정답으로 재사용하지 않습니다. Core, WPF 실제 명령 경로, 실제 OmniEdit EXE 수동 조작은 서로 다른 증거이며 대체했다고 보고하지 않습니다.

## 18개 기능 검증표

아래는 Core 검증의 대표 입력·예상 출력입니다. `\n`은 개행, `\t`는 탭, `\u0301`은 결합 악센트, `""`는 빈 문자열이며 표시된 공백도 비교 대상입니다. 같은 대표 연산을 CRLF·LF·CR로 확인했습니다. 각 행의 `Core 사례`는 `tests/MyTextEditor.Core.Tests/TransformAuditTests.cs`의 이름이며, `UI 사례`는 `tests/MyTextEditor.Performance/TransformAuditVerification.cs`의 이름입니다. UI는 별도의 명시적 예상 문자열을 사용합니다.

|---|---|---|---|---|---|

## 실행 결과와 수정 근거

- Core: 전체 **43개 테스트 통과**. 신규 감사는 예상 출력 100개와 잘못된 입력 11개를 각각 3회 실행했습니다. 출력뿐 아니라 미리보기와 요약 통계의 일치도 확인합니다.
- `--transform-audit`: 18개 모두 **미리보기 → 적용 → Undo → Redo**, **바로 적용 → Undo**를 원문 복원 후 각각 3회 통과했습니다. 이는 WPF 버튼 이벤트와 실제 Scintilla 편집기를 사용하는 검증입니다.
- 추가 UI 검증: 빈 구분자로 줄 합치기, 음수·빈 분할 구분자 오류, 0글자·빈 문서의 변경 없음, 연속 적용과 옵션 변경, 오래된 미리보기의 덮어쓰기 방지, 비동기 정리 도중 문서 이동·편집기 해제 이후 결과 폐기를 통과했습니다.
- 테스트 안내창에서 확인 버튼의 실제 ID가 2인 것을 확인하고 자동 응답을 수정했습니다. 비활성 테스트 창이 사용자 최대화 설정을 상속하던 문제는 테스트 창을 일반 상태로 명시해 해결했습니다. 제품 검사를 삭제하거나 약화하지 않았습니다.

| 발견한 문제 | 재현 | 수정과 회귀 근거 |
|---|---|---|
| 번호 증가 정수 범위 초과 | 시작 `2147483647`, 두 줄에 번호 추가 | 내부 증가값을 `long`으로 계산. 두 번째 `2147483648` 확인 (`numbers-overflow`) |
| 잘못된 작업 값이 기준 미일치로 가려짐 | 없는 기준과 잘못된 `TrimOperation` | 작업 종류를 먼저 검증. `ArgumentException` 확인 |
| 빈 구분자 줄 합치기를 UI에서 차단 | `a\nb`, 구분자 비움 | 분할만 빈 구분자를 거부. UI 결과 `ab`와 Undo 확인 |
| 변경 없음에도 적용·Undo 오염 가능 | 0글자 삭제, 빈 문서의 빈 줄 제거 | 입력·결과 본문을 비교해 적용하지 않음. 문서·Undo·수정 상태 유지 확인 |
| 개행만 바뀐 결과를 변경 수 0으로 무시 | `a\r\nb\rc\n`을 LF로 정리 | 줄 변경 수 대신 실제 본문 차이로 판단. Core `mixed-eol` 출력 확인 |
| 긴 한 줄의 하이라이트 초기화 지연 | 합치기 후 빈 문서 로드 | 덤프의 `ClearUserHighlights → CharToBytePosition` 확인. UTF-8 바이트 길이를 사용하는 네이티브 초기화로 변경 후 아래 300MB 검증 완료 |

## 대용량 측정

Release, 줄 바꿈 표시 OFF, 1,000자 단위 ASCII 입력. 30MB/300MB는 각각 30,000,000/300,000,000바이트입니다. 각 결과는 예상 전체 문자열과 비교했으며, 아래는 하이라이트 초기화 수정 후 한 차례 측정입니다. 연산 시간은 백그라운드 변환만, 전체 시간은 원문 읽기·변환·편집기 반영·UI 처리를 포함합니다. UI 지연은 15ms Dispatcher 타이머의 최대 간격으로, 입력 응답 시간을 직접 측정한 값은 아닙니다.

| 크기 | 작업 | 전체 ms | 연산 ms | 최대 UI 타이머 간격 ms | 출력 |
|---|---|---:|---:|---:|---|
| 30MB | 앞뒤 공백 제거 | 310.2 | 60.7 | 213.1 | 일치 |
| 30MB | 포함 줄 삭제 | 45.8 | 4.6 | 19.6 | 일치 |
| 30MB | 구분자 분할 | 292.2 | 64.9 | 202.6 | 일치 |
| 30MB | 한 줄 합치기 | 4,753.6 | 51.9 | 4,160.0 | 일치 |
| 300MB | 앞뒤 공백 제거 | 2,825.8 | 608.5 | 2,066.0 | 일치 |
| 300MB | 포함 줄 삭제 | 192.0 | 29.9 | 78.1 | 일치 |
| 300MB | 구분자 분할 | 3,506.1 | 859.1 | 2,501.5 | 일치 |
| 300MB | 한 줄 합치기 | 55,701.3 | 510.5 | 44,597.2 | 일치 |

300MB 합치기는 결과가 맞더라도 긴 UI 지연이 남아 있습니다. 연산보다 UI 반영 구간의 비중이 크며, 이 표만으로 원인을 확정하거나 성능 문제가 해결됐다고 판단하지 않습니다. 추가 병목 조사 및 수정 이후 수치는 별도로 구분해 기록합니다.

## 화면과 미완료 항목

기본 화면은 짧은 요약만 표시하고 상세 규칙·예시는 접어 둡니다. 현재 문서 전체 적용과 미리보기·Undo 안내도 상세 설명에 배치했습니다. 숫자 제거·빈 줄·구분자 처리 규칙은 상세 설명과 도움말에서 확인할 수 있습니다. 기능 ID와 매크로 파일 형식은 유지합니다.

- 실제 Release OmniEdit EXE에서 짧은 기본 설명과 상세 펼치기·접기는 확인했습니다.
- 실제 EXE의 18개 기능별 물리 조작, 도킹·분리 패널과 즐겨찾기 진입 확인은 아직 전체 완료하지 않았습니다. 자동 UI 검증으로 대체했다고 보고하지 않습니다.
- Solarized Light 미세 조정 및 최종 테마 회귀, 병목 추가 조사, 최종 빌드·검토 결과는 후속 기록 대상입니다.
- 이번 범위에는 릴리즈 배포가 포함되지 않습니다.

### 최종 성능 및 회귀 확인

커서 줄·열 상태 조회를 native 위치 기반으로 바꾸고 열 값을 문서 revision/위치/탭 너비 기준으로 재사용했습니다. 300MB 단일 줄의 반복 줄·열 조회는 측정 해상도상 0.0ms로 감소했습니다. 줄 합치기 전체는 30MB 3334.7ms(UI 최대2670.4ms),300MB 32095.8ms(UI 최대26228.5ms)로 여전히 지연됩니다. 한 번의 측정이며 완전한 응답성 개선으로 해석하지 않습니다.

최종 수정본 --transform-audit, --tool-window-appearance, --document-display 통과. Solarized Light 기본 글자는 #4F656C로 변경했고 보조 글자/배경은 유지합니다. 실제 배포 EXE18개 전체 수동 검증은 남아 있으며 릴리즈 노트에도 명시합니다.
